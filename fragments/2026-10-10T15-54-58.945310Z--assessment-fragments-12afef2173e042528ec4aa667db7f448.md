回应用户三问：脱敏入库（用户已定）、JSON 是否更好、成本与宿主无关。均为建议，未实现。
1) JSON：格式不是关键。创世谱系 S3 已因“又发明一个新 substrate”否决 events.jsonl；沿用同一 fragments 文件夹、同一 append.py，新增 kind 为对话的片段即可，正文用 markdown 轮次，不另起 JSON 存储。用户提到的“之前的 JSON 保存方式”具体指什么未核实。
2) 成本：本会话 Claude 日志 631KB/336 行，其中用户与助手的对话文本仅约 1.1 万字符；工具输出、文件快照占绝大部分。只存对话文本（不存工具输出与思考）可缩小到约 2%，且密钥多出现在工具输出里，同时降低泄露面。对话片段不进开机内容，只供 grep 与事后提炼，因此不增加开机 token。
3) 宿主无关：不依赖钩子。本机已有 Claude(~/.claude/projects, 228M)、Codex(~/.codex/sessions, 3.0G，jsonl，首行 session_meta)、opencode、gemini、cursor 的本地日志。做一个“拉取式”收集器：每宿主一个小解析器，按项目目录过滤，脱敏后追加；在开机时运行（把开机步骤合并为一条命令，仍是两步），无钩子的宿主同样可用；有钩子的宿主可额外挂同一脚本作加速而非前提。
限度：各宿主日志格式无官方稳定承诺，须逐个核实；脱敏只能是模式匹配，不能保证零泄露，故建议首次推送前人工抽查且仓库保持私有；没有本地日志的宿主（网页端）收集不到；非 git 项目也能用，因为触发点是开机而不是提交。
