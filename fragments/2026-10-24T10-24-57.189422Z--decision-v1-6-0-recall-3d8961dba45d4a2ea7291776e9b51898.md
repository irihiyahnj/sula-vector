来源：device-memory（651 片段、258 条在力判断、pi 与 Claude Code 同时写）2026-10-24 实测三个缺陷：两个会话互相认领 +N this turn；查找靠 grep 猜词，被推翻的片段与替代者并列返回不加区分；判断与其对话原文之间没有任何链接。

决定：
1) 读者永远是模型，所以检索主路径是一份它能整读、按意思挑的清单，而不是正则或 embedding（embedding 需要算力，本机不算、云端会外发内容，也违反不建索引）。实现为只读 skill tools/sula_vector/skills/recall.py：无参数列出全部在力判断与目标（含标签）；id 前缀追溯：替代链与现行者、引用它的现行规则、双向引用、同轮记录与该轮原文；字面多词匹配（不分大小写）覆盖片段与原文，按命中词数、在力优先、新者优先排序。全部在读取时连接，老记录无需迁移。render.py 不为此增长（只加 standing 计数与查阅说明）。
2) 新可选字段 session（= agent 开机时记下的 session_start）：note.py/rules.py --session，turn.py --since 同时签名原文。回执 = 本会话自上一条签名原文以来的记录；未签名的以 ? 标出；他人签名的不出现。
3) 当场记判断：本会话本轮没有签名的判断时，turn.py 打印 [sula] ! no judgment this turn，除非用 --no-judgment "<why>" 给出理由（写进原文头）。不拒绝写入。
4) annotation 的 tags 借给其 refs 的片段，用于给老记录补检索词而不改动它们。
5) 约定版本 1.5；migrate.py TOOLING_FILES 加入 skills/recall.py，并加测试防止 skill 漏装。

验证：Mac 上 144 个单测、doctor、--for-agent 逐字节、示例 doctor、handoff_scenarios 全过；在 ~/work/同仁 副本上升级演练通过（2177 片段，升级前后 doctor 问题数相同）。未验证：读者用 recall 答历史题是否优于 grep（没做考试）；CI 3.10–3.12 待推送后跑（Mac 只有 3.9.6）。
