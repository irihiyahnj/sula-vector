回应用户“现在面临的问题如何解决”。根源：记录靠 agent 在工作中途自己判断“这条值不值得记”，这个判断是唯一失败点，而且漏了没人看得见。
建议：
1) 记录从“判断”改为“照抄”：每轮收尾一条命令（暂名 close），agent 把用户本轮原话和自己给出的回答原文经 stdin 交给 ingest（脱敏 → kind=transcript 片段），无需判断记什么。命令写进 AGENTS.md，任何读 AGENTS.md 的工具都适用，不依赖宿主日志或钩子。
2) 每轮末尾必出一行回执（如 `[sula] 本轮已记录`）；没有这行就是没记，用户在任何工具里一眼可见，可当场让 agent 补。现有“无变化不显示”的收尾规则要相应改。
3) 判断仍用 note.py 记；有了原文，之后可随时用更强的模型重新提炼、核对漏记，模型质量只影响初稿。
4) 有钩子的宿主可自动调用同一条命令，是加分项，不是依赖。
限度：agent 完全不遵守 AGENTS.md 时仍会漏，但表现为缺回执，失败可见而非沉默。代价：回答原文要多写一遍（多出的输出 token 约等于回答长度）；存储只含对话文字，本会话约 1.1 万字符，量级可忽略；每轮一个片段，片段数会明显增长。
硬约束：irihiyahnj/sula-vector 在 GitHub 上是 PUBLIC（2026-10-10 gh repo view）。原文即使脱敏也会公开发布，正则挡不住人名、客户名、业务内容。原文只应进私有仓库；公开仓库是否收原文、收在哪里，要另行决定（“fragments 旁不另设状态目录”是现有规矩），且每个项目启用前先查仓库可见性。
